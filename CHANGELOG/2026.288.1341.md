**On the file's own comment.** The installed file is the ORG's caller, from the same source as
plugin-box, layer-charly-build and plugin-deploy-pod, whose tags work — and it now differs from
them in exactly one region: this file's comment block. That block previously described the
trigger design using another repository's merge counts, schedule-run counts and PR numbers, which
are not this repository's history; it now attributes each measurement to where it came from
(the origination repo for the counts, upstream for the PR reference) and no longer claims that
every opencharly repo carries this caller, which is not the case. The executable lines are
unchanged. The org-wide question of whether the shared caller should carry repo-neutral
commentary is recorded on opencharly/.github#204.

**The first-merge gap is a known, measured limit, not an oversight.** The canary
(opencharly/layer-nerdctl#7) proved that installing the caller does not tag the merge
that installs it: `push:[main]` cannot observe auto-merge squashes, and
`workflow_run` needs a validator completion after the file exists. This repo's
untagged merges are therefore backfilled add-only on their merged HEADs as part of
this rollout, rather than left with a silent gap.
