# 2026.288.1444 — fix(workflow)!: take the R3 readiness-bounds fix from the source (follow-up to #8)

## Summary

Takes the R3 fix for the org caller's readiness probe from its source. This repository landed the caller
before [opencharly/plugin-box#51](https://github.com/opencharly/plugin-box/pull/51) named and
config-sourced the two bounds the probe polls on, so this copy still polls with unnamed inline literals:

```js
const deadline = Date.now() + 5 * 60 * 1000;            // unnamed magic number
await new Promise((r) => setTimeout(r, 20 * 1000));     // unnamed magic number
```

**R3 bans poll-retry and, unconditionally, unnamed magic-number tuning.** Its only stated carve-out is
`exec.Command("podman"/…) where charly is the orchestrator`, which does not apply to a workflow step. The
bounds are now named env values, and the timeout message interpolates the window it actually used rather
than asserting a hardcoded `5m`:

```yaml
        env:
          READINESS_WINDOW_MS: "300000"   # 5 minutes: hard deadline for the merge to land
          POLL_INTERVAL_MS: "20000"       # 20 seconds between readiness checks
```

Behaviour is unchanged — the same 5-minute deadline and 20-second interval; only the source of the two
values moved. This is the producer-first order: the source was fixed and merged first, and the copies
follow.
